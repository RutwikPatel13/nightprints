# CLAUDE.md

Context for Claude Code sessions on this repo.

## What this is
A print generator for kids nightdresses and pajamas, built for a friend who sells them. SDXL base plus one LoRA per style family. Two output modes: `pattern` (seamless all-over tile) and `placement` (single character, transparent background).

## Hard constraints
- Must stay free. Training and dataset generation run on Kaggle's free T4. No paid APIs, no paid hosting.
- SDXL base 1.0 only (CreativeML Open RAIL++-M allows commercial use). Do not switch to Flux dev; its license is non-commercial.
- Training data is generated by SDXL and hand-curated. Do not add scrapers for Pinterest, Instagram or other artists' work.
- Content is for young children: nothing scary, no sharp teeth, no blood, no text or logos in the art.
- Must fit in 16 GB VRAM: fp16, gradient checkpointing, 8-bit Adam, batch size 1.

## Style families
- `dino` (current): see configs/styles/dino.yaml and docs/style-guide.md.
- `sweet` (next): cherries, bows, hearts. Config in configs/styles/sweet.yaml. Separate LoRA. Do not mix with dino.

## Conventions
- Python 3.10+, type hints, small functions. Library code in `src/nightprints`, entry points in `scripts/`.
- Every script takes `--style <yaml>` and reads paths from it.
- Never commit anything under data/ or outputs/.
- Keep post-processing CPU-only so it can be tested on a Mac.

## Work in phases
1. Dataset generation and curation
2. Captioning and LoRA training
3. Eval (CLIP score, style consistency, seam score) with a with/without LoRA comparison
4. Generation CLI and Gradio app

## Known gotchas
- Kaggle runs a newer diffusers: VAE slicing lives on `pipe.vae`, not the pipeline. models.py handles both.
- In notebook `!` cells, IPython treats `{...}` as Python. Use `( ... )` subshells, not `{ ...; }` groups.
- Base SDXL ignores "white background" unless it comes first in the prompt and scenery is in the negative.
